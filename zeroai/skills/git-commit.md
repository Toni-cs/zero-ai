# Git 提交信息规范

## 结构

    <type>: <中文主题行，不加句号，<= 50 字>

    <为什么这么改，而不是改了什么。>
    <用户可见的行为变化，写进正文。>

## type 取值

- `feat` 新增能力
- `fix` 修复缺陷
- `test` 补测试 / 修测试
- `refactor` 不改行为的结构调整
- `docs` 只改文档
- `chore` 构建、依赖、脚手架

## 正文必须回答的问题

1. **为什么改** —— 触发这次改动的具体问题是什么？
2. **改了什么** —— 涉及哪些文件/模块，为什么选这个改法？
3. **怎么验证的** —— 跑了什么命令，结果如何？

## 禁止

- 只写"修改了 xx"而不写为什么
- 主题行带句号或末尾标点
- 把未验证的改动写成"已修复"
- 中英混杂到读不通（中文项目就用中文写正文）
